# 한국어 조판과 텍스트 레이아웃

글꼴·혼용·줄바꿈·여백·확대·넘침이나 화면의 읽기 흐름을 다룰 때 읽는다.
제품의 기존 타이포그래피 역할과 토큰을 먼저 확인한다. 새 글꼴이나 일괄 CSS 규칙을 기본 해법으로 삼지 않는다.

## 실제 글꼴과 위계

제목, 본문, 레이블, 보조 설명과 수치의 역할이 시각적·의미적으로 구분되는지 본다.
실제 적용된 글꼴과 대체 글꼴에서 한글, 영문, 숫자, 괄호·문장 부호, URL과 코드가 함께 읽히는지 확인한다.
글리프 누락, 기준선과 폭 차이, 제공되지 않는 굵기의 합성 표시, 지원하지 않는 가변 글꼴 축을 살핀다.
외부 글꼴은 이용 조건과 로딩 실패·지연을 확인한다. 대체 글꼴에서도 내용과 조작이 사라지거나 잘리지 않아야 한다.

행 길이·행간·자간·문단 간격은 역할, 글꼴과 실제 폭에 맞춰 판단한다.
모든 제품에 최적인 px, 행간이나 글자 수를 선언하지 않는다.
텍스트 넘침을 숨기려고 글자 크기를 줄이지 말고 문안, 배치와 컨테이너 제약을 함께 고친다.
기존 토큰을 사용하고 새로운 공통 값이 필요하면 제품의 토큰 변경 절차를 따른다.

## 줄바꿈과 혼용

실제 한국어 영역의 언어 정보가 맞는지 확인하고, 해당 콘텐츠에 맞는 줄바꿈 정책을 선택한다.
`word-break: keep-all`과 `normal`은 문맥별 후보이며 어느 하나를 모든 요소에 강제하지 않는다.
긴 URL·식별자에는 필요한 경우 `overflow-wrap`을 검토하고, 코드·수식처럼 보존이 필요한 내용은 별도 읽기 경로를 둔다.
다른 언어와 코드까지 같은 규칙으로 묶지 않는다.

줄 끝·첫머리에 고립된 괄호나 문장 부호, 조사만 남는 줄, 제품명과 단위의 분리를 살핀다.
제목을 맞추려고 고정 `<br>`를 먼저 넣지 말고 문장 구조와 가용 폭을 확인한다.
NBSP나 전체 `nowrap`으로 내용을 묶거나 공백 여러 개로 정렬하지 않는다.
양끝 맞춤의 벌어진 어절, 지나친 음수 자간, 고정 높이 상자의 잘림도 실제 글꼴에서 확인한다.
필수 내용을 말줄임했다면 키보드와 터치에서도 전체 내용을 읽을 수 있어야 한다.

## 읽기와 조작의 의미

시각적 제목과 DOM 제목 계층, 문서 읽기 순서가 맞는지 확인한다.
레이블, 링크와 상태는 색·위치·애니메이션만으로 뜻을 전달하지 않는다.
보이는 버튼 문구와 접근 가능한 이름이 같은 행동을 가리키고, 이름에 보이는 문구가 포함되는지 확인한다.
본문을 이미지로 바꾸거나 조각난 문자마다 반복해서 읽히게 만들지 않는다.
긴 오류·처리 중 문구, 포커스 표시와 고정 영역이 본문이나 제어를 가리지 않는지 살핀다.

## 필요한 조건에서 직접 확인하기

| 조건 | 볼 것 |
| --- | --- |
| 제품의 대표 넓은 폭과 약 390 CSS px | 실제 제목·본문·버튼·표·오류가 읽히고 조작되는가? 필요한 좁은 폭은 제품 지원 범위에 맞춰 추가한다. |
| 200% 텍스트 확대와 사용자 간격 변경 | 고정 높이, 줄바꿈, 겹침 때문에 내용이나 기능을 잃지 않는가? 사용자 간격 검사 값을 기본 스타일로 강제하지 않는다. |
| 긴 한국어·영문 혼용·URL·수치 | 내용과 식별자가 보존되고 잘림·과도한 간격·페이지 넘침이 없는가? |
| 글꼴 지연·실패·대체 | 실제 사용 글꼴이 달라져도 읽기 순서, 필수 문구와 조작이 유지되는가? |
| 키보드와 상태 전환 | 이름·포커스·상태 안내가 실제 행동과 일치하고, 문구가 바뀌어도 제어가 가려지지 않는가? |

좁은 폭 재배치와 텍스트 확대, 사용자의 간격 변경은 별도 조건으로 확인한다.
문서·슬라이드를 다룬다면 실제 출력 크기와 해당 렌더러에서 확인한다.
검사한 소스·빌드, 브라우저/렌더러, CSS 폭, 확대, 글꼴과 상태, 조작 및 관찰 결과를 남긴다.
한 장의 스크린샷은 그 순간의 배치 근거다. 이미지 픽셀 크기로 CSS 폭이나 확대 비율을 추정하지 않는다.
정적 검사나 캡처만으로 반응형·키보드·확대·보조 기술 검사를 모두 통과했다고 하지 않는다. 실행하지 않은 항목은 그대로 남긴다.
