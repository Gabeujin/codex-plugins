# Pattern lifecycle

A repeated shape is not automatically a KGJ pattern. Admission is evidence-led and reversible.

| Stage | Meaning | Binding use |
|---|---|---|
| experimental | A bounded hypothesis in one real product flow | never a default |
| candidate | Evidence exists, but coverage or counterevidence remains incomplete | opt-in only |
| stable | Useful, unique, usable, accessible, consistent, and versatile all pass | supported default in declared scope |
| deprecated | A replacement and migration window are published | existing use only |
| removed | Runtime support ended after the migration contract | no |

`pattern-check` validates the record and fails a stable candidate unless all six criteria pass and at
least two active, passing, locally hashed evidence records resolve through `--evidence-registry`.
Arbitrary IDs and URL assertions cannot make a pattern binding. Deprecated patterns require a replacement or a concrete
deadline. Removal requires both a replacement and deadline so consumers retain a migration receipt.

A pattern owner must test worst-case content, error and empty states, keyboard operation, large text,
reduced motion, assistive technology, relevant devices, and at least one real product use before
promotion. Popularity and repetition are discovery signals, not admission evidence.
