# 공개 소스 검토

공개할 파일은 `PUBLIC-SOURCE-INVENTORY.json`에 경로와 출처 유형을 등록합니다. 새 파일은 목록에 없으면 검사를 통과하지 못합니다. 기존 파일을 변경해도 내용 검토와 PR 검토가 필요합니다.

## 자료를 가져오기 전에

- 공개 저장소에서 이미 배포한 소스와 공개용으로 새로 작성한 변경만 사용합니다. 회사 소스·업무 문장·내부 시스템·개인 기록을 복사한 뒤 이름만 바꾸지 않습니다.
- 테스트 입력은 새로 만든 가상 값으로 작성합니다. 실제 회사명·도메인·계정·토큰·작업 경로를 차단 목록이나 실패 예제에도 넣지 않습니다.
- 카탈로그, Dictionary, 진단 실행 폴더, 채팅, 캡처와 개인 검증 기록은 공개 저장소 밖에 둡니다. 원문 기사와 외부 자산의 권리는 각각 확인합니다.

## 목록과 출처

파일마다 아래 출처 유형 중 하나를 선택합니다. `baselineCommit`은 기존 공개 소스의 기준점이며 새 변경의 검증 성공을 뜻하지 않습니다.

| 유형 | 의미 |
| --- | --- |
| `existing-public-repository` | 기준 공개 소스에 있던 파일. 공개 이력 자체가 안전성·권리의 증거는 아닙니다. |
| `public-repository-change` | 공개 저장소를 위해 작성하거나 검토한 변경. 업무 원본에서 옮긴 자료에는 사용할 수 없습니다. |
| `synthetic-fixture` | 실제 사용자·업무 자료를 사용하지 않고 작성한 테스트 입력과 예제 |

목록에 등록했다는 선언만으로 내용 검토를 대신하지 않습니다. 새 자료의 작성 경로, 조건·수치·이름의 의미와 첨부 내용을 PR에서 함께 확인합니다. 자동으로 목록을 채워 검사만 통과시키지 않습니다.

## 이미지·글꼴·첨부

미디어마다 SHA-256, 내용·메타데이터 검토일, 저장소 안의 출처 문서를 기록합니다. 검토한 파일이 바뀌면 해시가 달라져 차단됩니다. 새 미디어도 검토 기록 없이는 공개할 수 없습니다.

화면에 표시된 이름·입력값·URL·실제 기록, EXIF·텍스트·연락처·편집 이력을 확인합니다. PNG의 텍스트·XMP·EXIF 청크는 공개본에서 허용하지 않으며 출처·크레딧은 별도 문서에 보존합니다. 글꼴 등은 라이선스 문서를 연결합니다. SVG와 소스에 포함된 텍스트도 별도로 읽습니다.

현재 미디어 목록은 기존 공개 데모·도식·출처가 있는 영상·글꼴에 한정합니다. 내용과 메타데이터를 확인한 기록이며 모든 숨은 데이터의 부재나 권리 자체를 자동 인증하지 않습니다.

## 실행과 확인 범위

검토한 새 파일을 명시적으로 stage한 뒤 실행합니다.

```powershell
node scripts/verify-public-source.mjs
node scripts/verify-release.mjs
```

첫 명령은 추적 중인 작업 파일의 목록·출처·미디어 해시와 기존 토큰·경로·파일 유형 검사를 실행합니다. 패키징은 정확한 Git commit의 소스를 읽고 ZIP 전체 목록·바이트를 대조한 뒤 같은 검사를 다시 실행합니다.

`--directory` 검사에서는 패키징 도구의 루트 `release-manifest.json`을 소스 목록에서 제외하고 일반 내용 검사만 적용합니다. 이 파일의 출처·전체 필드·바이트가 정확한 commit과 일치하는지는 반드시 `package-release.py --check`로 확인합니다. directory 검사만으로 패키지 무결성이 검증된 것은 아닙니다.

검사는 회사 관련 문장의 의미나 출처의 진실성을 자동 판단하지 않습니다. 새 공개 내용은 독립 검토자가 실제 diff를 읽어야 합니다. 전체 Git 과거 이력 정리와 이미 공개된 외부 사본의 삭제는 별도 작업이며 이 검사가 수행하지 않습니다.

공유용 진단이 필요하면 Daily Check의 선택형 `share` 명령을 사용합니다. 자유 입력과 원본 캡처가 포함된 보고서는 공유본과 구별해 로컬에 보존합니다.
