## Daily Check 공유 요약

`report.py share <run> --output <new-directory>`는 완료된 원본을 읽고 새 폴더에 `share.json`과 `share.md`를 만듭니다. 고정 점검 ID·상태·재계산한 집계만 남기며 자유 입력 근거·경로·URL·시각·도구명·시스템 정보는 복사하지 않습니다. 원본 보고서는 그대로 보존합니다.

기존 출력 경로, 잘못된 점검 ID·상태·중복 키·비정상 수치·과대 입력은 거부합니다. 공유본은 호출자가 기록한 상태의 요약이며 독립 인증이나 전체 기능 정상 동작의 증거는 아닙니다.

## 공개 소스와 첫 사용

- 공개할 경로와 출처 유형을 명시적으로 등록합니다. 등록되지 않은 파일은 검사에서 차단합니다.
- 미디어의 검토 기록을 SHA-256에 연결합니다. 파일이 바뀌면 다시 검토해야 합니다. PNG 텍스트·XMP·EXIF 메타데이터도 차단합니다.
- 전시에 사용하는 PNG 이미지의 비필수 텍스트 메타데이터를 제거했습니다. 픽셀·크기·색상 프로필과 별도 출처·크레딧은 유지합니다.
- doctor가 marketplace 목록을 읽고 Daily Check를 별도 진단 유형으로 표시합니다. 첫 사용 표에도 네 플러그인을 모두 안내합니다.
- 기존 행동 시나리오를 유지하고 Daily Check 사례를 더해 32개 시나리오와 4개 겹침 사례를 정의했습니다. 정의·합성 회귀를 실제 모델 행동 평가로 주장하지 않습니다.
- README를 용도 선택 → 설치 → 작은 첫 요청 순서로 정리했습니다.

자동 검사는 회사 관련 내용의 의미나 출처의 진실성·권리 자체를 판단하지 않습니다. 실제 diff와 이미지·메타데이터의 독립 검토를 함께 수행해야 합니다. [공개 소스 검토](PUBLIC-SOURCE-REVIEW.md)를 참고하세요.

## 호환성과 검증

플러그인 ID·MCP 도구·데이터 경로·스키마는 유지합니다. 카탈로그·Dictionary·메모리를 자동 이전하거나 다시 쓰지 않습니다. Daily Check의 기존 원본 보고서 명령도 유지합니다. 새 플러그인은 추가하지 않았습니다.

검증 명령은 `node scripts/verify-release.mjs`이며, 정확한 commit의 소스 패키지 검증·격리 설치·원격 CI 결과는 각각 별도로 확인합니다. Canvas 브라우저·빌드 검사는 저장소 CI에서 실행합니다. 실제 브라우저·운영체제 알림·수집·모델 행동은 실행한 근거 없이 통과로 설명하지 않습니다.
